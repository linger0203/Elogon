下线 _单文件版/ 整个目录（v1.0.18 · 减负）沁的指令：「把 _单文件版/ 整个目录下线」。
  为什么现在可以下线：v1.0.17 把原型本体升格为 index.html 之后，它本身就是零依赖的单文件 —— 而那份 444 KB 的「自包含版」内容停在 v1.0.15 的快照、生成脚本还已经丢了。再单独维护它纯属负担。要单发一个文件给研发，直接发 index.html 即可。

  处置方式不是直接 rm：先 cp -r _单文件版 _过程产物/_归档/_单文件版_已下线 留退路，再 rm -rf _单文件版。归档里含 E登录Mac原型.html（445,323 B）与 说明.md（7,524 B），日后真要找回东西还在。

原型本体升级为 index，删除 linked-prototype.html（v1.0.17 · 大幅简化）沁的原话：「linked-prototype.html 原型是我想要的有流程轨道也有本页说明，我觉得它更适合 index，是否可以直接删除 index，将此作为 index」—— 追问后选定「真删掉，内容搬过去」。
  为什么这个判断是对的：旧 index 是个 11.9 KB 的「壳」，自己什么都没有，靠 <iframe> 去装 177 KB 的原型；而原型本体独立打开时本来就是轨道展开 + 工具条 + 状态面板 + 日志 + 本页说明浮层全在—— 沁要的那个形态，原型自己就有，壳反而是多余的中间层。一个入口页如果只是「用 iframe 装另一个文件」，那它就是纯粹的转发器，没有理由存在。
  这一刀省掉了什么：① 少一层 iframe（说明页嵌原型时不再有「iframe 套 iframe 转发」）；② 少一套 postMessage 落点接力 —— 以前 index 顶栏要靠原型推消息才知道用户停在哪，现在顶栏和原型在同一个文档里，直接读状态；③ 少一处「改名就断链」的风险点。
  但有两条死结必须先解：① 说明页会自己嵌自己 —— 它原本 iframe src="linked-prototype.html?embed=1&rail=1"，文件没了就 404。解法：把说明页那三处（:249 iframe 的 src、:412 load() 的 base、:450 新标签打开）全部改指向 index.html，因为 ?embed=1 这套参数在 index 上依然生效（参数逻辑是原型自带的，跟文件名无关）。② 单文件版的生成脚本指向旧文件 —— 已同步文档说明。
  实测结果（19 项全绿）：index 独立打开 folded=false、轨道宽 290px、工具条 flex、状态面板与日志俱在、「本页交互说明」按钮在、浮层默认关着（走 .open 类 + transform，不是 display，所以 display 恒为 flex 属正常）；说明页右栏 9 组仍在、iframe 指向 index.html?embed=1&rail=1&node=bind 且实渲染出 828×464；说明页点「← 联动原型」正常落回 index.html。
  验证方法提醒：轨道节点的类名是 .node 不是 .n；判断浮层开没开要看 classList.contains('open')，不能看 getComputedStyle().display。

做一份单文件自包含版（v1.0.15 · 新增 _单文件版/E登录Mac原型_单文件版.html）起因是沁的一个提问：「单独发送 index.html 给研发预览，这个名称被我改了，为什么我单独发送这个文件就打不开了」。
  查下来根因是：index 不是页面，是「壳」—— 它用 <iframe src="linked-prototype.html?…"> 装原型、用 <img src="assets/logo-color-128.png"> 取头像。只发这一个文件时，两个依赖都不在旁边：实测原型请求 404（iframe 一片空白）+ 头像请求 404（裂图），合起来就是研发说的「打不开」。
  改名还额外打断了 3 条回程链（都硬编码了 index.html）：E登录_Mac版_交互说明.html:457、变更与修订记录.html:119 与 :131 —— 已一并改指向新文件名。
  解法：原型整份内联进 iframe 的 srcdoc、两张 logo 转 data:URI、在原型 <head> 前注入一段 shim 把 URLSearchParams 包一层——因为 srcdoc 文档的 URL 是 about:srcdoc、location.search 恒为空，原型读不到 embed=1&rail=1 就会按「独立打开」渲染，左侧流程轨道这一页的意义就没了。注入让原型本体一行都不用改。
  验证 46 项全绿，最重的一层是 file:// + 孤立目录（= 研发真实「收到一个文件、双击」场景）：零外部依赖、logo 不裂、原型渲染、轨道 12 节点全在、点轨道外层标题跟着变、换页后仍正常。

原型向外层播报落点（v1.0.14 · 联动原型）拆页带出一个新问题：外层不知道用户在原型里点轨道跳到了哪一页。index 顶栏那颗「重载」要落在用户正看的那页才有意义；说明页的右栏也得跟着左侧轨道走，否则「左边已切到设置、右边还停在首次绑定」，看说明的人会以为是自己点漏了。
  为什么不让外层自己读：iframe 走 file:// 时是不透明源，外层碰 frame.contentWindow.location 直接抛 SecurityError —— 只能由里往外推。原型新增 notifyHost()，在 go()（界面内跳转）/ goForce()（轨道点节点）/ 启动段 三处各推一条 {t:'e-login-view',node,name}；独立打开时 window.parent === window 直接返回，全程 try/catch，通知失败绝不影响原型本身。
  落在 9 条流程之外的界面（退出成功页、注销过程中的几步）时什么都不做：这些界面本就没有说明条目，硬切一个「最近的分组」只会让人对错号；这一条也保住了条目级落点（M-MENU-007 → panel-off-new）刚写下的「正在看：M-MENU-007」不被冲掉。
index 的跳转按钮改名 btnNotesPage（v1.0.14 · index）联动原型工具条上本就有一个 id="btnNotes"（「本页交互说明」浮层开关）。两者在不同文档里，技术上不会打架，但同一个 id 出现在两处，读代码的人迟早看串 —— index 那颗跳转按钮改名 btnNotesPage。
未登录面板按有无绑定记录分流（v1.0.10 · 联动原型 + 平铺 03）用户报「退出登录时打开页面没有用户，写着『您好，』」。查下来根因不是缺兜底，而是一条路径走错了地方：「未登录面板 → 点【登录统一身份】→ 登录页」这条路径，在全新机器（本机从未绑定过）的场景下 `S.user` 为空，登录页回显成「您好，」——没人登录过，却在对一个不存在的人问候。修法不是补一个「您好，朋友」的兜底（那只是把空话说圆），而是消除产生空前置的路径：`panel-off` 这个面板同时服务两种场景（已绑定但退出登录 / 全新机器），去向必须分流。
  有绑定记录 → 按钮「登录统一身份」，进登录页，可一键登录；无绑定记录 → 按钮「关联统一身份账号」，进首次绑定引导页。绑定关系区的文案同步区分：「未登录 / 已绑定 XXX，可一键登录」vs「尚未关联 / 本机还没有关联统一身份账号」。平铺 03 新增状态四 · 全新机器，把这一态画出来。
绑定成功自动分配档案手机号（v1.0.10 · 交互表 + 联动原型）手机号无法从账号名派生，旧版在档案表里留空、由用户手填，于是短信登录与忘记密码-短信渠道都没有值可用。本轮改为绑定成功那一刻自动发号并写进档案，规则（沁定）：138 开头 + 按序编号，第 n 个绑定账号取 1381000000n，全部为合法 11 位号码。同一账号重复绑定拿到同一个号（幂等，按档案已有记录返回）；解绑不回收。发号动作挂在 commitBind() —— 那是绑定记录的唯一写入口，保证「有绑定必有号」，不会出现两处各写一次而对不上。
手机号输入校验（v1.0.10 · 三处覆盖）口径（沁定）：严格 11 位国内手机号（/^1[3-9]\d{9}$/），边输边验 + 按钮置灰。判定收敛成一个 isPhone()，三处共用：① 短信登录/绑定的按钮可用性（bindReady() 的短信分支）；② doBind() / doLogin() 的短信提交前置校验；③ 忘记密码「获取验证码」前（仅手机号渠道，邮箱与钉钉不套用手机号规则）。
  踩过一个坑：发号算式第一版写成 '138' + String(1000000+n).slice(-9)，拼出来只有 10 位，自己发的号过不了自己的校验（T4 实测 是否合法: false）。已改为 '138' + String(10000000+n).slice(-8) = 11 位。教训：取值规则与格式校验规则必须自洽，发号方要拿校验函数自测一遍。
联动原型加「本页交互说明」栏（v1.0.11 · 联动原型）研发看原型时手里只有画面，没有「这一屏有哪些交互点、预期是什么」。本轮在最右侧加一栏，与左侧流程轨道相对：轨道是「整条流程的节点地图」（跳到某一步），说明栏是「眼下这屏有什么」（对照着做）。默认收起，工具条上「本页交互说明」按钮展开；切界面时自动刷新——切到设置就是设置那 6 条，切到忘记密码就是 PWD 那 8 条，不用手动找。
  每条交互点带蓝色 ID 标签（与交互表 / PRD 对照用），点开展示触发 / 预期 / 异常 / 提示语原话 / 页面五段，全部取自《交互表 v1.0》。panel 与 panel-off 两态归并成同一份清单（登录态判定不该影响「这屏能做什么」）。
  数据由 _过程产物/r31/ 的脚本从交互表导出后内嵌（原型保持单文件、零依赖、双击即开）；界面→交互点的映射写在脚本里并逐条核过，72 条全部有落点，改表后重跑脚本即可同步。
index 左侧直接用联动流程轨道（v1.0.13 · index + 联动原型）起因是沁的一句：「index 直接用联动轨道流程放在左侧，页面交互说明还放在原来的位置互不影响」。
  为什么之前做不到：v1.0.9 起 index 用 iframe 嵌原型，src 是 ?embed=1。而 embed=1 一口气做了两件事 —— 加 embedded（嵌入形态）和 加 folded（轨道收起）。更绝的是还有这么一条 html.embedded .shell.folded .rail-open{display:none}：嵌入形态下连「展开轨道」的按钮也一起藏了。于是 index 里根本没有任何入口能看到轨道，研发只能靠右侧文字脑补流程。
  本轮把两件事拆开：新增 ?rail=1 —— 嵌入形态（工具条照旧收掉、说明浮层照旧隐藏）但轨道展开。index 改用 ?embed=1&rail=1&node=xxx，左侧于是直接显示「联动流程轨道」，可点节点跳转；右侧 430px 的 72 条说明位置、宽度、行为全部不动，两边互不影响。四处都要带上 rail=1（初始 src / load() / 重载 / 点条目），漏掉任何一处，点一次条目轨道就没了。
  顺手补了一个闭环：轨道既然能收起，就必须能再展开 —— 否则收起来就回不去了。所以 rail-on 时把「展开轨道」按钮放行（选择器升到 5 个 class，无论写在哪都压得住原来那条隐藏规则）。实测：收起 → 按钮出现 → 点它 → 轨道回来，闭环成立: true。
  还加了窄屏兜底：左侧多了 290px 轨道 + 右侧固定 430px，视口 ≤1150px 时中间原型会被压到 430px 以下。加两条媒体查询，只在窄屏收窄右栏（≤1200 → 370px，≤1100 → 330px），≥1200px 完全不动 —— 1280 / 1366 / 1440 这些常规办公显示器不受任何影响。加后几何：≥1100px 都能保证原型桌面区 ≥480px。
「本页交互说明」改为右侧滑出浮层（v1.0.12 · 联动原型）v1.0.11 把说明栏做成 .shell 的第三个 flex 成员，三栏（桌面区 + 流程轨道 + 说明栏）并排时宽度不够，桌面区被压扁——而桌面区里装的是模拟 macOS 窗口，压扁后窗口跟着缩，原型就不像原型了。本轮按沁的建议改成右侧滑出的浮层：position:fixed 脱离文档流，靠 transform:translateX(100%) → 0 滑入滑出（走合成层，不触发布局重排），桌面区宽度从此恒定。实测开关前后桌面宽 968px 不变、窗口宽不变。
  三个开关口：工具条「本页交互说明」按钮、浮层头部 ✕、点浮层外部（遮罩只接点击、着色透明，不让原型变暗）；另加 Esc，优先级排在模态框之后——有模态框时 Esc 只关模态框，不会一次关两层。
  浮层根元素挂到 <body> 下而不是留在 .shell 里（.shell 是 flex 容器，留在里面会被压/被裁）。嵌入模式（?embed=1）下浮层与遮罩一起隐藏——那是给 index 当 iframe 用的，index 自己已有右侧说明。
  本轮踩了一个很隐蔽的坑，值得单独记：把浮层 DOM 搬到 </body> 前之后，DOM 排到了 <script> 后面，而 v1.0.11 遗留的顶层语句 document.getElementById('notesBody').addEventListener(...) 就拿不到元素 → null.addEventListener 抛 TypeError → script 顶层执行中断。后果是所有 var 赋值集体丢失（FP_PROFILE 变 undefined），v1.0.10 的发号与手机号校验功能全部失灵；而函数声明会提升，样式与结构检查也照样全绿——表面上是「浮层工作正常」，实际已经崩了。修法是把这个监听改为委托到 document，彻底摆脱 DOM 时序依赖。已同步在脚本里加护栏：凡顶层裸绑 DOM，断言对应元素必须排在 <script> 之前；验证脚本新增 T0「script 顶层执行完整性」，逐个确认关键 var 真的被赋过值。

退出后登录页：两个入口分层重排（v1.0.5 · 平铺 04 + 联动原型）上一版把「忘记密码 · 注销绑定账号」用 · 并排右对齐放在主按钮下方 —— 问题在于破坏性操作与日常操作权重相同、还紧挨着，手滑就会点到注销。本轮按视觉层级重排为三段：【登录】主操作 → 【忘记密码】单独一行右对齐、紧贴主按钮（它与密码框同源，属同一个操作带）→ 【注销绑定账号】沉到窗口最底部独立区，细线隔开、左对齐、灰色小字、悬停才变红。危险操作与主流程物理隔离，是防误触最直接的手段。
修掉忘记密码页两个未定义函数（v1.0.5）重构时发现的既有缺陷：联动原型 forgotPage() 里的密码框写着 oninput="checkPolicy(...)"、主按钮写着 onclick="doReset()"，但这两个函数从未定义过 —— 也就是说在旧版里填密码不会有任何策略反馈，点「确认修改」直接抛 ReferenceError，流程是断的。本轮已补齐：checkPolicy() 做策略实时反馈 + 自动开合浮层 + 同步按钮禁用态；doReset() 做四项前置校验（验证码已过 / 有网络 / 两次一致 / 策略合规）后再提交。另新增 renderKeepPw()，在验证码解锁触发重渲染时把已填密码原样写回，避免丢输入。
退出后登录页：只认本机绑定账号（v1.0.6 · 平铺 04 + 联动原型）这个页面此前是「谁登都行」，但本机 OS 账号与统一身份账号是 1:1 绑定 —— 放别的账号进来会和绑定关系自相矛盾。本轮在提交环节加拦截：账号与本机绑定账号不一致时不通过、不跳转，账号框与密码框一并标红，并用错误条明确告知「登录失败，本机已绑定账号：zhangsan」。联动原型里这条规则落在 doLogin() 的 view==='loginagain' 分支，复用既有 errBlock()；改动输入即撤掉失败态（清 S.data.loginErr + 拆掉红框与错误条），不必刷新页面。自动演示脚本也补了一段「用 lisi 登录被拦下」的走位，免得这条规则只能手点才看得到。
撤掉退出页的注销入口 + 页面收窄（v1.0.6 · 平铺 04 / 05 + 联动原型）上一版（v1.0.5）刚在退出后登录页底部加过「注销绑定账号」入口，本轮判定逻辑不成立并撤回：那一刻用户处于未登录状态，没有身份可验证，却允许发起解除绑定这种不可逆操作，等于把最危险的动作放在一个未经认证的入口上。现在注销只保留唯一入口：菜单栏面板（已登录态、一级平铺），必须走完二次确认 + 身份验证。连带把平铺 04 页与 05 页重复承载的注销流程三张卡删掉，04 页收窄为「退出后登录页」本身（正常态 + 失败态两张卡），注销流程全量归 05 页。
  遗留风险：原绑定用户离职后，新用户既登不进去（账号不匹配）、也进不了菜单栏面板（面板要求已登录）去注销 —— 这条路径目前是死锁，已列入待确认。
退出后登录页：登录判定拆两层 + 死锁自助解绑（v1.0.7 · 平铺 04 + 联动原型）本页此前只比账号名，密码对不对压根没管（v1.0.6 的漏洞）；加上 v1.0.6 撤掉了注销入口，「原绑定用户离职 → 新用户既登不进去、也进不了菜单栏面板注销」这条路径就成了死锁。本轮把提交动作拆成两层：① 凭据认证（账号密码对不对，由 IAM 服务端回答）→ ② 账号比对（凭据对了，再看是不是本机绑定的那个）。第 ② 层失败时才在页面底部条件渲染出「注销绑定账号」入口 —— 此刻凭据已由 IAM 认证过，「来者是合法员工、只是不是本机绑定的那位」已成立，验证在这一刻已经完成，所以这条解绑路径不再重复验证密码，确认即解绑；第 ① 层失败则只报凭据错误，绝不透露本机绑定了谁。实现上新增 S.data.canUnbind 标志，与失败态同生共死 —— 改输入时既要摘错误条和红框，也要一并摘掉这个入口按钮（漏摘会留下一个语义已失效的按钮）。
  与 v1.0.6 撤回入口并不冲突：当时反对的依据是「未登录态没有身份可验证」，本轮补上了前置条件（入口仅在第 ② 层失败时出现）—— 验证已在提交那一刻完成。
  实跑时又逮到一个：第一版只让 doCancel() 跳过密码校验，但二次确认弹窗的「确认注销」按钮仍指向 toCancel2()，会跳到「请输入当前账号密码」那一屏 —— 本机绑的是别人的账号，新用户根本不知道那个密码，看到这个框就直接卡住了。已改为 lock 路径确认按钮直连 doCancel()，并给 toCancel2() 补守卫兜底。
「验证本机 macOS 系统密码」方案作废（v1.0.7）曾考虑在解绑前让 E 登录验一遍本机 macOS 系统密码。技术上不成立：macOS 客户端拿不到系统密码 —— LocalAuthentication 只返回布尔结果、且弹的是系统自己的面板（界面样式、文案、按钮都不受 App 控制）；Authorization Services 也不把密码交给调用方。也就是说这条路原型画得出来、实现落不了地，还会让界面语言分裂成两套。改为「由 IAM 认证来者身份」：与登录提交合并（二次确认文案明确写出「你已通过统一身份认证」），零额外步骤，且身份判定发生在服务端、可信。
忘记密码：账号行按本机绑定账号返显（v1.0.7 · 平铺 02 + 联动原型）账号值此前写死成 zhangsan 那一套。本轮改为 fpProfile(S.bindIam) 按「本机已绑定的那个账号」派生 —— 绑了 zhangsan 就返显 138****8888 / zhangsan@corp.com / zhangsan，绑到 lisi 就返显 lisi@corp.com / lisi（手机号在档案里查不到，留空交给用户填，不编造）。档案表里没有的账号走派生规则：邮箱 = 账号 + 企业域名、钉钉 = 账号本身。联动原型的自动演示会把本机绑定账号从 zhangsan 换成 lisi，切换后返显值同步易主。
「本机已绑定账号」改为读绑定记录，不再是常量（v1.0.8 · 联动原型 + 平铺 02 / 04 / 05）症状：不管在绑定页输入哪个账号，退出后登录页都声称「登录失败，本机已绑定账号：zhangsan」——用自己刚绑的账号登录反而被拦。根因是那个值压根不是派生出来的：S.osUser 是个写死的常量（对象初始值写一次、resetAll() 复位写一次，连自动演示脚本里都得手动塞一次），而绑定流程从头到尾没写过它 —— 绑谁都不影响它。
  更深一层是语义混用：同一个字段，在绑定页那行被当作「本机 macOS 账户名」展示，在退出页又被当作「绑定记录里的统一身份账号」做比对。而这两个值在设备转交场景下必然分离 ——新员工用的是自己的 macOS 账户，机器上的绑定记录却还留着原员工的 IAM 账号。
  本轮拆成三个各司其职的字段：macUser（macOS 账户名，系统给的只读值）、bindIam（本机绑定记录里的统一身份账号 ——「本机已绑定账号」的唯一真相来源）、user（上次登录的账号，只喂「您好，XXX」回显）。
  规则约束：bindIam 的写入点唯一（绑定成功那一刻的 commitBind()）、清空点唯一（注销成功那一刻的 commitUnbind()）；退出登录不动它（这正是「退出」与「注销」的分界线）；为空时不做账号比对（没有记录可比，不凭空拦人）。这两个函数是全项目仅有的两处赋值，别处一律不准直接改。右侧状态面板新增「本机 macOS 账户」「本机绑定记录」两行，来源可当场核对。

v1.0.8 把「本机已绑定账号」的来源定死了：它读绑定记录（写入点唯一 = 绑定成功，清空点唯一 = 注销成功），不再是常量 —— 绑谁就报谁。
